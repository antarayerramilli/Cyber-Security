Security & Architecture Information

Educational overview of the cryptographic mechanisms securing OpenBallot elections.

Ed25519 Cryptography

Digitally signs ballots so the system can verify who authorized them without sharing secrets. Prevents forgery and guarantees non-repudiation.

SHA-256 Hashing

Creates one-way cryptographic digests used to uniquely identify ballots and permanently bind sequential blocks in the ledger.

Proof-of-Work (PoW)

Requires verifiable computational work to seal each block, making past election history computationally infeasible to rewrite.

Blockchain Ledger

Links blocks together in an append-only sequence where any unauthorized modification immediately breaks cryptographic hashes down the chain.

Nakamoto Consensus

Allows distributed nodes to converge on a single authoritative ledger history by adopting the longest valid chain across peers.

Transaction Mempool

Temporarily holds valid submitted ballots while awaiting block mining, enforcing duplicate-submission protection at the staging layer.
